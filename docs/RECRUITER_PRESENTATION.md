# Como organizei a apresentação profissional

Este documento registra a lógica de curadoria do portfólio para evitar dois problemas: repetir a mesma competência em todos os projetos e transformar o site em uma lista de tecnologias.

## Projetos principais

| Projeto | Evidência principal |
| --- | --- |
| Mala Direta | automação/n8n em produção e confiabilidade |
| Produção Operacional | implantação, adoção e operação |
| Proposta Comercial | processo, documentos/e-mail e impacto mensurável |
| CarreiraPessoal | produto, arquitetura, evidências e engenharia |
| Catálogo Operacional | backend, busca e dados operacionais |
| Postagem Redes | IA aplicada, APIs externas e revisão humana |

## Recortes complementares

- Portal: arquitetura empresarial e modularidade, ainda em desenvolvimento/revalidação;
- Central ISO: Qualidade, regras determinísticas, rastreabilidade e piloto técnico;
- Compass UOL: dados/cloud;
- Manutenção em Campo: ativos, checklists, evidências e histórico;
- HelpDesk: adoção de sistema interno;
- Hubora/StudioCad/sites: produto, domínio específico e web.

## Regra editorial

Eu tento escrever cada case na ordem **problema → decisão → implementação → resultado → limite real**. A tecnologia aparece como resposta ao problema, não como o assunto principal.

Quando existe tela real que pode ser publicada com segurança, ela tem prioridade sobre mockup ou ilustração. Quando o ambiente é confidencial, uso dados sintéticos, referência autorizada ou arquitetura sanitizada.

## Fonte de verdade

Currículo, portfólio e GitHub não devem divergir em cargo, métricas, estado do projeto ou tecnologia atribuída a um case. O currículo continua curto; o portfólio expande contexto; o repositório deixa código, decisões e testes disponíveis para quem quiser aprofundar.
