01

Context and problem

Isolated systems, spreadsheets, files and processes increased duplication and forced non-technical users to learn multiple interfaces.

02

What I did

Product conception, architecture, backend, operational frontend, events, integrations, testing, documentation and governance.

03

How I built it

FastAPI, PostgreSQL, Redis, MinIO, WebSockets, asynchronous workers, RBAC, encrypted vault, transactional outbox, Action Intents and n8n contracts.

04

What is demonstrated

  • 19 backend domains and 51 documented migrations.
  • Code modules used internally by 3 people.
  • n8n treated as an executor, not the source of truth.

What this case does not show

It is a public reference architecture; modules have different maturity levels and do not represent a fully certified platform.

If the operation grew

I would consolidate modules in waves with SSO, centralized monitoring, tested backups, load testing, versioned contracts and an official ERP integration.

Public evidence contains no credentials, personal data or sensitive internal information.
